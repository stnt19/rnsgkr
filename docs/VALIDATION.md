# 검증 기록

현재 버전은 질문·답변 전용입니다. 아래 카메라·비전 검증은 제거 전 버전의 이력입니다.

## 질문·답변 전용 전환 (2026-10-29)

카메라 UI, 영상 스트림 처리, 비전 모듈과 의존성 목록, 클래스 매핑 예시 및 인식 API를 제거했습니다. 교범 그림은 답변의 설명 자료로 유지합니다. 첫 화면은 질문 입력이며 추천 질문도 실제 정비 질문으로 변경했습니다.

Python 27개 테스트와 JavaScript 구문 검사가 통과했습니다. 삭제한 카메라 자산과 인식 API가 404를 반환하는지, 부품 메타데이터에 비전 설정이 없는지, 정비 안내·사진·원문 연결이 유지되는지를 확인했습니다.

브라우저에서 카메라 메뉴가 없는 첫 화면, 정비 추천 질문, 질문 전송 후 설명·교범 그림·정비 단계가 표시되는 동작을 확인했습니다.

검증일: 2026-10-28 (한국 시간)

## 자동 검증

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
git diff --check
```

단위 테스트 5개 통과:

| 항목 | 확인 내용 |
| --- | --- |
| 주제별 검색 | 폐쇄망 구조, 8주 일정, RAG 기능, 정비 병목의 관련 페이지 검색 |
| 수리 질문 | 시동·토크값 질문에 자료 부족 안내와 6쪽 출처 제공 |

| 목표와 성과 구분 | 기대 효과 수치를 실측 결과로 표현하지 않는지 확인 |
| 후속 질문 | 개발 일정 이후 추가 설명 질문에서 8쪽 검색 |

JavaScript 구문 검사와 Git 공백 검사도 통과했습니다. 이 결과는 지정된 예시에 대한 검증이며 모든 질문에 대한 정확도를 의미하지 않습니다.

- 브라우저에서 초기 화면, 추천 질문 전송, 답변 출력 확인
- 6쪽 출처 창의 내용과 `/document#page=6` 원본 링크 확인
- 실제 수리 방법 질문에 근거 부족 안내 확인
- 새 대화로 초기 화면 복귀 확인
- 원본 PDF와 임시 화면 이미지가 Git에서 제외되는지 확인

## 아직 검증하지 않은 범위

- Ollama 모델의 실제 생성 응답과 모델별 근거 충실도
- 실제 정비 교범, DELIS, 장비 센서·영상 데이터 연동
- 다양한 모바일 장치에서의 실제 조작과 접근성 전수 검사

현재 버전은 제안서 내용을 확인하는 로컬 프로토타입입니다. 실제 진단이나 정비 의사결정에 사용하기 전에는 승인된 자료와 별도의 검증이 필요합니다.

## 차량 교범·사진 기능 추가 검증

같은 날짜에 렉스턴 스포츠 자료를 가져온 상태에서 **총 20개 단위 테스트**를 수행했습니다. 기존 5개에 더해 다음을 확인했습니다.

- 정적 HTML·CSS·JS 경로의 정상 응답, 등록되지 않은 부품 ID 거부
- 부품명·별칭·SGN 연결과 미등록 항목 처리
- 외부 API 응답에서 로컬 원본 경로·해시 제외
- 비전 모델 미설정·cloud 모델명·잘못된 이미지 처리
- 모의 비전 응답에서 허용된 후보만 반환하고 사용자 확인 요구
- 12종 부품 모두 개요 페이지가 실제 색인 범위에 포함되는지 확인
- 부품 선택 시 다른 부품 문서가 섞이지 않는지 확인
- 교범 응답의 원문 이미지 링크, 후속 질문의 부품 유지, 잘못된 문서 ID 거부

`test_maintenance.LocalManualTests`의 5개는 로컬 색인이 없으면 건너뜁니다. 비전 후보 모의 테스트에는 Pillow가 필요합니다. `requirements.txt` 설치 후 검사하세요.

추가 브라우저 확인:

- 파일 선택으로 교범에서 렌더링한 샘플 이미지를 넣고 미리보기·모델 미설정 안내 확인
- 배터리 직접 선택 후 위치·구성·공통 주의사항·카탈로그 참조 표시 확인
- PDF 572쪽 이미지가 실제 로드되는지 확인(너비·높이 확인 포함)
- 선택 부품의 증상 입력 → 교범 발췌·문서별 출처 표시 확인

부품 개요 12종은 텍스트로 확인했으며, 에어클리너·배터리·라디에이터·헤드 램프의 위치·구성 페이지는 렌더링하여 시각 검토했습니다. 선별된 모든 수리 절차·표의 정확성을 전문가가 전수 검수한 것은 아닙니다.

Android 실기기 카메라·USB 연결, 실제 비전 모델, 실제 차량 사진의 인식 정확도, 차량 고장 진단의 적합성은 아직 검증하지 않았습니다. 위 파일 선택 검증을 실제 카메라 촬영 검증으로 간주하지 않습니다.

## 실시간 카메라 전환 검증

정지 사진 파일 입력을 제거하고 `getUserMedia` 기반 미리보기·프레임 연속 분석으로 전환했습니다. 위 파일 선택 검증은 이전 버전의 기록입니다.

- Python **29개 통과**: 기존 20개에 모델 미설정, YOLO 우선순위, 가중치 누락 시 다운로드 금지, 클래스 매핑, 위치 좌표·점수 필터, 유효 프레임 검사, 동시 추론 거부, 모의 탐지 결과를 통한 저장 비활성화 확인을 추가했습니다.
- Node.js **8개 통과**: 중복 시작, 단일 요청 처리, 중지 시 취소, 늦은 결과 무시, 재시작 시 세대 분리, 오류 재시도 지연, 설정 오류 시 정지, 요청 제한 시간, 느린 추론에서 프레임 대기열이 쌓이지 않는 동작을 검증했습니다. 일부 테스트에서 여러 동작을 함께 확인합니다.
- 정적 자산 테스트에 `/live-core.js`를 포함했습니다.

모든 탐지 결과 테스트는 모의 모델을 사용합니다. 이 PC에 YOLO 패키지·학습 가중치가 없으므로 실제 영상 인식률·현장 지연 시간·Android 카메라 동작은 검증하지 않았습니다. 고속 탐지를 완료했다고 해석하지 않습니다. 설치 및 모델 연결 절차는 README를 참고하세요.

최종 브라우저 확인에서 실시간 카메라 제어 화면, 모델 미설정 안내, 정지 사진 파일 입력이 0개인 점, 부품 직접 선택 후 정비 원문 연결을 확인했습니다. 실제 카메라 권한을 허용하거나 PC 카메라 영상을 수집하지 않았습니다.

## 가공된 정비 안내와 그림 검증 (2026-10-29)

기본 답변을 원문 페이지 발췌에서 검토 요약과 그림을 포함한 안내로 변경했습니다. 이전의 원문 발췌 검증 기록은 변경 전 동작입니다.

- Python 38개 통과: 12종의 문장·단계·그림과 출처 연결, 원문 전체 미노출, 결로 질문의 흡습제 분기, 필터 방향·연료 프라이밍·냉매 회수 선행 조건, 교범 버전 변경·근거 누락 시 차단, 수치 질문 처리, 그림 영역·허용 ID 검사를 추가했습니다.
- JavaScript 구문 검사 통과. 연속 인식 루프는 수정하지 않았으며 기존 8개 테스트 결과를 유지합니다.
- 부품 개요 그림과 선택 작업 그림 15개를 실제 렌더링해 시각 검토했습니다. 장기간 결로 분기의 그림도 원본 페이지와 대조했습니다.
- 정리된 안내는 교범을 읽고 작성한 요약이며 전문 정비 담당자의 전수 검수나 실제 수리 성공을 의미하지 않습니다. 전체 작업 절차와 규정값은 원문 대조가 필요합니다.


### 질문 범위 및 근거 확인 (2026-10-30)

- 차량 정비·군학연계 자료 외 질문: 범위 밖 안내 (`reason: out-of-scope`).
- 차량 관련이지만 검토된 안내로 답할 수 없는 질문: 근거 부족 안내 (`reason: missing-evidence`). 두 경우 모두 출처와 정비 안내를 생성하지 않습니다.
- 부품명·SGN만 일치한다고 안내하지 않습니다. 질문 전체가 일반 설명·위치·점검·교환 등 허용된 요청 형태인지 확인합니다. 헤드램프 결로는 별도로 검토된 안내를 사용합니다.
- 수치, 가격, 교환 주기, 미검토 증상, 다른 부품을 섞은 질문은 추측하지 않습니다. 정비 PDF 전체를 의미적으로 판정하는 모델이 아니라 보수적인 규칙 방식이므로, 표현이 낯설면 근거 부족으로 처리될 수 있습니다.
- 이전 질문이 지원되는 경우에만 명확한 후속 질문에 부품을 이어받습니다. 기존 제안서 검색은 명시적인 제안서 주제에 한해 유지합니다.
- 검증: Python unittest 32개 통과. 범위 밖 질문, 부품명 포함 무관 질문, 미지원 수치·가격·증상, 명시 partId와 대화 이력을 통한 우회, 기존 안내의 출처 연결을 확인했습니다.
