# 개발 및 운영 참고

## 구성

| 파일 | 역할 |
| --- | --- |
| `server.py` | 표준 라이브러리 HTTP 서버, 문서 검색, 선택적 로컬 모델 호출 |
| `web/index.html` | 채팅·참고 문서 화면과 출처 대화상자 |
| `web/style.css` | 데스크톱·모바일 반응형 스타일 |
| `web/app.js` | 질문 전송, 대화 메모리, 출처 확인, 상태 표시 |
| `data/knowledge.json` | 원본 10쪽을 직접 검토한 쪽별 요약 및 검색 태그 |
| `tests/test_chat.py` | 검색과 응답 정책 단위 테스트 |

## 요청 흐름

1. 브라우저가 질문과 최근 대화 최대 6개 메시지를 서버에 전송합니다.
2. 서버는 한글 단어·2글자 조각의 빈도와 태그 일치를 점수화하여 최대 3개 쪽을 선택합니다.
3. 기본 모드는 요약 발췌를 반환합니다. 짧은 후속 질문은 직전 사용자 질문을 검색에 활용합니다.
4. `OLLAMA_MODEL` 설정 시 검색 문맥과 현재 질문을 로컬 Ollama에 전달합니다. 전체 대화를 모델에 보내지는 않습니다.
5. 모델 연결 실패 시 발췌 모드와 안내 문구를 반환합니다. 브라우저는 응답과 출처 버튼을 표시합니다.

현재 방식은 벡터 임베딩 기반 RAG가 아닌 경량 키워드 검색입니다. 규칙 기반 수리 질문 감지는 모든 표현을 포괄하지 못합니다. 검색 결과가 있다는 사실만으로 답변의 정확성을 보증하지 않습니다.

## API

모든 경로는 로컬 서버 기준입니다. 인증은 없으며 외부 운영용 API가 아닙니다.

| 메서드·경로 | 응답 |
| --- | --- |
| `GET /api/status` | 요약 페이지 수, 모델 설정명, 문서명, 원본 존재 여부 |
| `GET /api/pages` | 쪽별 제목·요약·태그 배열 |
| `POST /api/chat` | 답변, 출처 배열, 실제 답변 모드, 연결 실패 안내 |
| `GET /document` | 로컬 `data/source.pdf`; 없으면 404 |

질문 요청 예:

```json
{
  "question": "RAG 챗봇은 어떤 기능을 하나요?",
  "history": []
}
```

`question`은 공백 제외 1~2,000자 문자열입니다. `history`는 최대 12개 메시지이며 각 메시지는 `role`(`user` 또는 `assistant`)과 최대 4,000자의 `content` 문자열을 포함합니다. 전체 요청 본문은 24,000바이트 이하입니다. 잘못된 형식은 400, 본문 크기 제한 위반은 413, 허용되지 않은 Origin은 403입니다.

응답 필드:

- `answer`: 화면에 표시할 문자열
- `sources`: `page`, `title`, `text`를 포함하는 배열
- `mode`: `document` 또는 `local-model`
- `notice`: 선택적 모델 연결 실패 안내. 인사 응답에는 생략될 수 있음

## 설정과 실행

Python 3.10 이상을 사용합니다. `PORT` 기본값은 `8000`, `OLLAMA_MODEL` 기본값은 빈 값입니다. 환경변수를 설정한 후 서버를 재시작해야 반영됩니다. `.env` 파일을 자동으로 읽는 기능은 없습니다.

```powershell
git clone https://github.com/stnt19/rnsgkr.git
cd rnsgkr
python server.py
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 종료는 서버를 실행한 터미널에서 `Ctrl+C`입니다. 포트가 사용 중이면 다른 `PORT`를 지정합니다. 원본 파일이 없어도 문서 요약 검색은 동작합니다.

## 자료 갱신

1. 허가된 원본을 로컬 `data/source.pdf`에 배치합니다.
2. 원본을 검토하고 `data/knowledge.json`의 페이지 번호, 제목, 요약, 태그를 함께 갱신합니다. 현재는 한 문서를 전제로 합니다.
3. `web/index.html`의 문서 제목과 페이지 수 등 고정 표시를 확인합니다.
4. 예상 질문과 근거 페이지를 테스트에 추가하고 원본 링크를 확인합니다.
5. 서버를 재시작하고 브라우저를 새로고침합니다.

PDF를 바꾸는 것만으로 요약이 자동 갱신되지는 않습니다. 여러 문서·버전 지원에는 문서 ID, 출처 경로, 버전 모델 확장이 필요합니다.

## 데이터 취급과 운영 한계

원본 PDF, 임시 렌더링 이미지, 환경변수 파일은 `.gitignore`로 제외합니다. 요약 JSON은 소스와 함께 Git에 포함됩니다. 공유 범위가 바뀌거나 자료를 추가할 때는 요약의 공유 가능 범위도 검토해야 합니다.

질문·답변은 브라우저 메모리에만 남습니다. 요청 처리를 위해 최근 대화 일부가 로컬 서버로 전송되며, 모델을 설정한 경우 검색 문맥과 현재 질문이 로컬 모델로 전달됩니다. 현재 구현은 외부 API를 호출하지 않습니다.

루프백 바인딩, 입력 길이 검사, 기본 Origin 검사, 안전한 텍스트 렌더링을 적용했습니다. 인증, TLS, 사용자별 접근 제어, 요청 속도 제한, 다중 사용자 격리, 운영 감사 체계는 구현하지 않았습니다. 포트 공개나 외부 프록시 연결 전에 운영 보안 설계가 필요합니다.

## 차량 교범·실시간 카메라 기능 확장

`maintenance.py`가 로컬 교범 레지스트리·선별 본문 검색·PDF 페이지 렌더링을 담당하고 `vision.py`가 YOLO 어댑터·추론 잠금을 담당합니다. `scripts/import_manuals.py`로 색인을 만들고 서버 시작 시 한 번 로드합니다. `web/camera.js`는 미리보기·위치 상자·부품 확인·교범 탐색을, `web/live-core.js`는 단일 요청 연속 루프와 취소·세대별 응답 검사를 담당합니다.

| 메서드·경로 | 용도 |
| --- | --- |
| `GET /api/parts` | 대상 부품과 별칭, 색인 쪽수, 비전 모델 설정 여부 |
| `GET /api/part?id=battery` | 해당 부품의 본문, 관련 시스템 점검, 공통 주의사항, 카탈로그 참조 |
| `GET /api/manuals` | 원본 이름·쪽수·사용 범위·가용 여부. 절대 경로와 해시는 노출하지 않음 |
| `GET /manual-page?doc=engine&page=572` | 원본 페이지를 PNG로 렌더링 |
| `GET /document?doc=engine#page=572` | 등록된 로컬 PDF 열기 |
| `POST /api/identify` | 로컬 비전 모델에 JPEG·PNG·WebP를 전달하고 후보 반환 |

`POST /api/chat`의 선택적 `partId`로 부품을 명시할 수 있습니다. 부품명·별칭·SGN이 질문에 있거나 직전 부품 질문에 대한 후속 질문이면 교범 기반 안내로 연결합니다. 검토된 요약이 있으면 이를 사용하고, 버전·근거가 맞지 않으면 안내 불가 메시지와 관련 원문 링크만 반환합니다. 교범 응답은 로컬 LLM 생성 경로로 넘기지 않습니다. 부품명조차 명확하지 않은 일반 증상은 현재 전용 고장 트리로 처리하지 않습니다.

정비 출처는 기존 `page`, `title`, `text` 외에 `id`(`문서ID:PDF쪽`), `docId`, `document`, `printedPage`, `url`, `imageUrl`, `kind`를 포함합니다. 정리된 답변은 원문 전체를 기본 화면에 표시하지 않으며 문장별 근거와 접힌 원문 목록으로 연결합니다. 출처 모달에서만 원문 텍스트·페이지 이미지를 보여줍니다.

`/api/identify` 요청은 `{"image":"base64 문자열"}` 형식으로 전체 3,000,000바이트 이하이며 디코딩한 프레임은 2MB 이하입니다. 모델 미설정은 503, 잘못된 이미지·cloud 모델명은 400, 모델 연결·응답 실패는 502, 이전 추론 진행 중은 429입니다. 후보의 ID는 등록된 부품으로 제한하고 `needsConfirmation: true`를 반환합니다. 실제 학습 모델의 호출·인식률은 미검증이며 테스트에서는 모의 응답으로 어댑터를 검증합니다.

클라이언트는 카메라 스트림에서 프레임을 JPEG로 축소하고 인식 실행 중에만 전송합니다. `getUserMedia`에는 마이크를 요청하지 않습니다. 시작/중지·권한 대기 취소·화면 전환·탭 숨김을 처리하며, 재시작 전의 늦은 응답은 무시합니다. 원본 영상·프레임은 디스크에 저장하지 않습니다. 외부 공개·클라우드 런타임 설정은 별도 검토가 필요합니다.

`/api/parts`의 `vision`은 `backend`, `configured`, `available`, `message`, `intervalMs`, `timeoutMs`를 제공합니다. `available`은 파일·패키지 등 전제 조건 상태이며 실제 모델의 정확도나 추론 성공을 보증하지 않습니다. `YOLO_MODEL_PATH`가 설정되면 YOLO가 우선합니다.

YOLO 응답은 `backend: "yolo"`, `detections: [{id, name, score, box:[x1,y1,x2,y2]}]`, `candidates`, `inferenceMs`를 포함합니다. 좌표는 0~1의 정규화된 코너 좌표입니다. 후보는 서로 다른 부품 최대 3종, 상자는 최대 20개입니다. Ollama 응답은 `detections: []`로 위치를 추측하지 않습니다.

위치 상자는 영상의 원본 가로세로 비율과 같은 캔버스에 그립니다. 프레임은 이전 응답이 끝나야 다음 것을 추출하며, 예전 상자·후보는 YOLO 1.8초, Ollama 5초 후 지워 오래된 결과가 고정되지 않도록 합니다. 중지 시 브라우저 요청은 취소되지만 서버 실행 중인 추론을 강제 종료하지는 않습니다.

## 설명·그림을 포함한 정비 안내

`service_guides.py`는 `data/service-guides.json`의 검토 요약을 사용합니다. 각 문장에 페이지 근거를 연결하고, 등록된 교범 SHA-256 메타데이터와 필요한 페이지가 모두 맞는지 확인합니다. 최초 색인 때의 해시를 비교하는 것이며, 서버가 매번 원본 PDF 전체 해시를 다시 계산하는 것은 아닙니다. 원본을 바꿨다면 반드시 다시 가져오고 서버를 재시작해야 합니다.

정리된 응답은 `presentation: "service-guide"`와 `guide`를 포함합니다. `guide`에는 `title`, `subtitle`, `question`, `description`, `sections`, `warnings`, `figures`, `followUp`, `scope`가 있습니다. 각 문장의 `refs`는 응답의 `sources[].id`와 대응합니다. `answer`는 대화 이력 및 텍스트 클라이언트를 위한 같은 요약의 텍스트 버전입니다. 원문 페이지 전체를 답변으로 복사하지 않습니다.

`GET /manual-figure?part=battery&figure=location`은 허용된 부품·그림 ID만 받습니다. 그림 메타데이터의 고정 영역을 PDF에서 렌더링해 잘라 보여 주고 문서·페이지·캡션을 연결합니다. 임의 파일 경로나 클라이언트 지정 자르기 좌표는 받지 않습니다. 실패 시 화면에는 원문 열기 대체 안내를 표시합니다. 페이지 렌더링과 같은 라이브러리를 사용하며 최대 32개 그림을 서버 메모리에 캐시합니다.

현재는 검토된 12종 안내와 헤드 램프 결로용 분기가 있습니다. 일반 증상 입력은 부품별 점검 안내로 연결되며, 모든 고장 코드·차량 옵션에 맞는 진단을 생성하지 않습니다. 측정 조건이 필요한 수치 질문에는 검증되지 않은 단일 값을 만들어 답하지 않습니다.
