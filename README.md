# 정비온 · 군학연계 정비 지식 챗봇

안드로이드 태블릿의 실시간 카메라 부품 인식과 렉스턴 스포츠 2023 정비교범 검색을 연결하는 로컬 웹 프로토타입입니다. 12종 부품의 점검·탈거·장착 관련 원문 130쪽을 선별했습니다. 기존 군학연계 개발 제안서 10쪽의 요약 질의응답도 유지합니다.

기본 흐름은 **카메라 시작 → 연속 프레임 분석 → 인식 후보 확인 → 증상 입력 → 관련 교범 발췌와 원문 확인**입니다. YOLO 탐지 모델을 연결하면 부품 위치 상자와 이름이 영상 위에 표시됩니다. 인식에는 별도 학습 가중치가 필요하며 현재 포함되어 있지 않습니다. 모델이 없으면 카메라 미리보기와 직접 선택만 동작합니다. 고장을 영상만으로 확정하지 않습니다.

## 실행

Python 3.10 이상에서 실행합니다. 정비자료 가져오기·원문 이미지·비전 입력 검증에는 아래 패키지가 필요합니다. 제안서 요약 검색만 사용할 때는 표준 라이브러리만으로 실행할 수 있습니다.

```powershell
python -m pip install -r requirements.txt
python scripts/import_manuals.py --directory '정비 PDF 7개가 들어 있는 폴더의 절대 경로'
python server.py
```

브라우저에서 http://127.0.0.1:8000 에 접속합니다. 포트는 `PORT` 환경변수로 변경할 수 있습니다. 서버는 로컬 루프백에만 바인딩됩니다. 원본 PDF는 `data/source.pdf`에 넣으면 출처 창에서 열 수 있습니다. 원본 파일, 임시 이미지, 환경변수 파일은 Git 추적에서 제외합니다.

`data/source.pdf`는 기존 개발 제안서용입니다. 차량 교범 7개는 가져오기 시 원래 위치를 등록하므로 복사할 필요가 없습니다. 파일을 옮기면 가져오기를 다시 실행하고 서버를 재시작하세요. 원본과 추출 본문·절대 경로를 포함한 `*.local.json`은 Git에서 제외합니다.

## Android 태블릿

**카메라 시작**에서 브라우저 카메라 권한을 요청합니다. 후면 카메라 우선으로 연속 미리보기를 제공하며 파일 촬영·업로드 단계는 없습니다. 인식 중에는 긴 변 640px의 JPEG 프레임을 추출하여 한 번에 하나씩 분석합니다. 녹화하거나 프레임을 저장하지 않습니다. 권한·기기 없음·카메라 사용 중 오류를 구분해 안내합니다.

**인식 일시정지**는 분석만 멈추고 미리보기는 유지합니다. **카메라 중지**, 다른 화면 전환, 탭 숨김은 분석 요청과 카메라 트랙을 함께 해제합니다. 후보를 확인하거나 부품을 직접 선택하면 인식을 일시정지하여 선택한 부품이 자동으로 바뀌지 않도록 합니다.

카메라 접근에는 HTTPS 또는 localhost 같은 보안 컨텍스트가 필요합니다. 일반 `http://PC의-LAN-IP:8000`은 태블릿 카메라 접근에 사용할 수 없습니다. [MDN 카메라 접근 문서](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

PC에서 실행하는 서버에 태블릿이 접속해야 합니다. 태블릿의 `127.0.0.1`은 기본적으로 PC가 아닙니다. 개발용 USB 연결은 Android SDK Platform-Tools의 `adb`와 사용자가 허용한 USB 디버깅이 준비된 경우 다음처럼 포트를 전달할 수 있습니다.

```powershell
adb devices
adb reverse tcp:8000 tcp:8000
```

그 후 태블릿 브라우저에서 `http://127.0.0.1:8000`을 엽니다. 종료 후 전달을 해제하려면 `adb reverse --remove tcp:8000`을 실행합니다. 이번 작업에서 기기의 USB 디버깅 설정 변경이나 실제 태블릿 연결은 수행하지 않았습니다. Wi-Fi 배포는 별도 HTTPS·인증 설계가 필요하며 현재 서버를 외부에 공개하지 않습니다.

## 실시간 인식 설정

### YOLO 부품 탐지

렉스턴 부품에 대해 학습한 **로컬 탐지용 `.pt` 가중치**를 별도로 준비해야 합니다. 기본 COCO 모델은 대상 12종의 학습 모델로 간주하지 않습니다. 앱은 가중치를 자동으로 다운로드하지 않습니다.

```powershell
python -m pip install -r requirements-vision.txt
$env:YOLO_MODEL_PATH = 'C:\models\rexton-parts.pt'
$env:VISION_CLASS_MAP = 'C:\models\rexton-classes.json'
python server.py
```

모델 클래스 이름이 `battery`, `air-cleaner` 같은 부품 ID와 같으면 클래스 매핑을 생략할 수 있습니다. 그렇지 않으면 클래스 번호 또는 모델 라벨을 부품 ID에 연결하는 JSON을 지정합니다. `data/vision-classes.example.json`은 형식 예시이며 **실제 모델의 클래스 순서와 대조한 뒤 수정해야 합니다**.

YOLO 결과의 정규화된 위치 좌표와 점수로 화면에 상자를 그립니다. 매핑되지 않은 클래스와 0.5 미만 점수는 제외합니다. 표시하는 탐지 점수는 검증된 정확도나 고장 확률이 아닙니다. [Ultralytics 추론 결과 문서](https://docs.ultralytics.com/modes/predict/)

### 로컬 비전 언어모델

Ollama에 설치한 **로컬 이미지 입력 지원 모델**이 있을 때만 사용합니다.

```powershell
$env:OLLAMA_VISION_MODEL = '이미 설치한 로컬 비전 모델 이름'
python server.py
```

카메라 시작 후 프레임을 로컬 서버와 `127.0.0.1:11434`의 Ollama로 연속 전송합니다. 응답은 등록된 12종 중 최대 3개 후보로 제한하고 사용자가 확인해야 정비자료로 연결합니다. 이 경로는 전체 화면의 후보 분석이며 위치 상자를 제공하지 않습니다. 응답이 느리면 수초~수십초 간격이 될 수 있어 고속 객체 탐지와 구분합니다. YOLO를 설정하면 YOLO가 우선합니다.

YOLO는 최소 500ms, Ollama는 최소 2초 간격을 기준으로 **이전 응답이 완료된 후** 다음 프레임을 분석합니다. 실제 갱신 속도는 장비와 모델에 따라 달라지고 30FPS 등을 보장하지 않습니다. 클라이언트 요청 취소 이후 서버 추론이 계속될 수 있어 서버 전체에서 추론을 하나로 제한하고, 처리 중인 추가 요청은 429로 반환합니다. 오류는 지연 후 재시도하고 설정 오류나 연속 3회 실패 시 일시정지합니다.

이름에 `cloud`가 들어간 모델은 차단합니다. 로컬 주소라도 Ollama 자체의 프록시·클라우드 설정까지 앱이 보증하지는 않으므로, 폐쇄망 운영자는 실제 온디바이스 모델과 런타임 설정을 확인해야 합니다. 이 차량에 대한 인식 정확도는 아직 평가하지 않았습니다.

## 답변 방식

- 기본: 외부 호출 없이 한국어 단어·2글자 조각과 태그로 관련 쪽을 검색하고 검토 요약을 발췌합니다. 생성형 AI가 아니며 임의 질문을 모두 이해하는 기능은 없습니다.
- 선택: 별도로 설치하고 실행한 Ollama의 로컬 모델을 연결하면 검색한 문맥으로 답변을 생성합니다. 모델 설치는 이 프로젝트가 자동으로 수행하지 않습니다.

```powershell
$env:OLLAMA_MODEL = '이미 설치한 모델 이름'
python server.py
```

로컬 모델 주소는 `127.0.0.1:11434`로 고정되어 있습니다. 연결 실패 시 문서 발췌로 전환하고 이를 표시합니다. 생성 답변도 원문과 대조해야 합니다. 대화 기록은 화면 메모리에만 유지되고 새로고침·새 대화에서 초기화됩니다. 브라우저 저장소나 서버 DB에 저장하지 않습니다. HTTP 기본 접근 로그에는 요청 경로와 상태만 남습니다.

## 데이터와 구현 범위

`data/knowledge.json`은 OCR 전문이 아니라 사람이 페이지를 읽고 정리한 요약입니다. 표지의 95%·98%와 기대 효과 수치는 제안 목표이며 검증 성과가 아닙니다. 문서의 현재·완료 표현을 실제 사업 진척으로 단정하지 않습니다.

차량 교범을 가져오면 명시한 부품명·별칭·SGN으로 관련 안내를 찾습니다. SGN은 정비 작업 식별 코드로 주문 품번이 아닙니다. 품번은 카탈로그의 생산 시점·사양·옵션과 실제 차량 정보를 대조해야 합니다.

현재 12종 부품은 교범을 검토하여 다시 쓴 설명·점검 항목·정비 작업 개요를 제공합니다. 긴 원문을 답변에 그대로 붙이지 않고 관련 사진·도해와 주의사항을 배치합니다. 각 설명·단계의 원문 버튼과 접힌 근거 목록에서 출처를 확인할 수 있습니다. 헤드 램프 결로·습기는 일반 어셈블리 탈거 대신 검토한 흡습제 작업 안내를 우선합니다. 이 요약은 별도 생성 모델 없이 동작하며, 모든 자유로운 증상을 새로 진단하는 생성형 기능은 아닙니다.

`data/service-guides.json`과 `service_guides.py`가 설명·단계·주의사항·그림 범위와 페이지 근거를 관리합니다. 가져온 교범의 SHA-256 메타데이터가 검토 버전과 다르거나 필요한 페이지가 누락되면 기존 요약을 제공하지 않습니다. 표·도면·측정 조건·체결값과 전체 선행/후속 작업은 원문으로 확인합니다. PDF의 사진을 잘라 보여 주는 기능은 문서 내부의 검토된 범위만 허용하며, 사용자가 촬영한 사진을 변형하지 않습니다.

YOLO 연동 코드는 제공하지만 전용 학습 가중치, DELIS, AR, 예측 정비 모델과 실시간 운영 대시보드는 포함하지 않습니다. 인증·권한 관리·보안 검증을 마친 폐쇄망 운영 시스템은 아닙니다. GitHub 소스 보관과 외부 서비스 배포는 별도이며, 실행 서버는 로컬에서 동작합니다.

다음 단계는 승인된 장비별 교범·정비 이력 확보 → OCR 품질 검증 → 절/표 단위 인덱싱 → 질문별 근거 정답셋 검증 → 내부망 인증·접근 제어를 포함한 운영 배포입니다. 새로운 자료를 추가할 때는 `knowledge.json`의 문서 식별자와 출처 모델부터 확장해야 합니다.

## 검증

```powershell
python -m unittest discover -s tests -v
node --test tests/live-core.test.cjs
```

Python 38개와 JavaScript 8개 테스트로 교범 검색·가공 안내의 페이지 근거와 그림 범위·주의사항·버전 검사, 부품 매핑, 탐지 좌표 필터, 모델 누락, 연속 처리·취소·재시도·오래된 응답 무시를 검증합니다. 모델 연동은 모의 결과로 확인했으며 Android 실기기·현장 영상·학습 모델의 인식률은 아직 미검증입니다.
